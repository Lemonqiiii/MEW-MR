## 决策 #1: 项目基础设施架构 — 2026-06-04

- **背景**: 项目启动，需要确定 Claude Code 中的工作方式和信息组织架构
- **选项**:
  - A: 单文件 CLAUDE.md (所有信息集中)
  - B: 三层 Context 体系 (Tier 1 常驻 + Tier 2 按需 + Tier 3 知识库)
- **选择**: **方案 B — 三层 Context 体系**
- **理由**:
  - 综述项目信息量大（50-150篇论文），单文件无法承载
  - 分层体系与 Claude Code 的 memory/hooks 机制天然匹配
  - Tier 1 保持精简避免上下文污染，Tier 2/3 按需检索节省 token
- **影响**: 决定了后续整个项目的信息组织方式

## 决策 #2: 编码Agent触发方式 — 2026-06-04

- **背景**: 需要在每次增量进展后留下结构化记录
- **选项**:
  - A: 纯手动触发
  - B: Stop hook 自动触发
  - C: 两者结合 (Stop hook 提醒 + 手动执行)
- **选择**: **方案 C — 两者结合**
- **理由**:
  - Claude Code Stop hook 无法直接运行 agent，只能发提醒
  - 手动触发确保编码Agent在用户确认后执行，避免错误记录
  - Stop hook 提醒作为兜底机制，防止忘记记录
- **影响**: settings.json 配置 + 用户工作习惯

---

## 决策 #3: Tier 3 知识库存储方式 — 2026-06-04

- **背景**: 文献笔记需要高效存储和检索
- **选项**:
  - A: 纯 Markdown 文件 (docs/ 目录)
  - B: 纯 Memory 系统
  - C: 混合方案 (docs/ 存文献笔记 + memory/ 存元指针)
- **选择**: **方案 C — 混合方案**
- **理由**:
  - 文献量大（50-150篇），纯 memory 会爆炸
  - Markdown 人类可读写，git 友好
  - Memory 存项目状态/关键发现/决策等「元信息」提供快速导航
- **影响**: 目录结构设计、Agent 检索策略

## 决策 #4: 综述类型选择 — 2026-06-04

- **背景**: 确定综述是系统综述还是叙述性综述，影响方法学要求、检索全面性和PROSPERO注册
- **选项**:
  - A: 系统综述/荟萃分析（需PRISMA、PROSPERO、双人筛选、偏倚风险评估）
  - B: 叙述性综述（灵活、聚焦机制综合）
- **选择**: **方案 B — 叙述性综述**
- **理由**: 主题广泛（肿瘤内在+TME+获得性三大维度），机制多样性不适合定量合并；综述目的是提供理解框架而非定量效应量估计
- **影响**: 无需PROSPERO注册、无需双人筛选、检索全面性要求低于系统综述（但数据库覆盖缺口仍需声明）

## 决策 #5: Tier 2 数据库不激活 — 2026-06-04（事后记录于2026-06-05）

- **背景**: 按 database-coverage.md 激活决策表，本综述涉及药物/生物制剂(ICIs)→应激活 Embase；涉及临床试验→应激活 Cochrane CENTRAL。但 VPN 不可用，无机构访问权限。
- **选项**:
  - A: 等待 VPN 恢复 → 延期项目
  - B: 跳过 Tier 2，仅 PubMed/Europe PMC + Semantic Scholar
- **选择**: **事实上的方案 B — 跳过 Tier 2**（未做正式决策）
- **实际过程**: 搜索Agent 完成了 Tier 1 自动检索后，未执行 Step 0（数据库需求评估）和 Step 2（生成 Tier 2 检索清单），导致：
  - `manual-search-checklist.md` 保留模板占位符
  - 用户从未被提示"请连接VPN执行Tier 2检索"

- **影响**: 
  - 可能遗漏 Embase 独有的药理学文献（2,900+ PubMed 未索引期刊）
  - 可能遗漏 Cochrane CENTRAL 独有的未发表试验记录
  - 稿件缺少检索局限性声明（已于2026-06-05修复）
- **教训**: 项目快速推进时，Agent 设计中的"分支决策点"（Step 0/Step 2）不能被跳过；即使 VPN 不可用，也必须触发兜底流程

## 决策 #6: 编码Agent双模式架构 — 2026-06-05

- **背景**: 编码Agent原设计为单体4-Part工作流，但在整个项目周期中从未被触发，导致SESSION_LOG空白、MILESTONES未更新、Git提交稀少
- **选项**:
  - A: 保留单体设计，仅加强提醒
  - B: 拆分为轻量模式（2-3任务/次）+ 完整模式（每Phase）
- **选择**: **方案 B — 轻量+完整双模式**
- **理由**: 
  - 降低执行心理成本（"快记"仅需秒级）
  - 提高触发频率（每2-3子任务 vs 每Phase）
  - 完整模式保留审计能力（效率+安全+Harness数据）
- **影响**: CLAUDE.md 命令表、agent-specializations.md Agent 0 定义、settings.local.json Stop hook
