# 引用验证协议 (Citation Verification Protocol)

> 定义逐条引用验证的标准操作流程、风险分层策略和判定标准。

---

## 核心原则

**每条声明必须能追溯到其引用的文献。** 如果声明与引用文献的实际内容不一致，标记为"引用-声明不匹配"。

---

## 一、验证粒度与分层策略

### 全量验证三层架构

```
Layer 1: 存在性验证 (100% 引用)
    ↓
Layer 2: 摘要级验证 (100% 引用，有摘要的)
    ↓
Layer 3: 全文级验证 (核心引用，抽样或全量)
```

### Layer 1: 存在性验证

| 检查项 | 方法 | 工具 |
|--------|------|------|
| PMID/DOI 有效 | 查询 PubMed/DOI 注册 | WebFetch |
| 文献确实存在 | 验证作者/年份/期刊匹配 | 比对元数据 |
| 未被撤稿 | 检查撤稿数据库 | Retraction Watch API |

### Layer 2: 摘要级验证

**触发条件**: 所有有摘要可获取的引用

**验证内容**:
1. 读稿件中引用该文献的**完整段落**（前后各2句）
2. 获取文献的**摘要/结构化摘要**
3. 逐条比对：
   - 稿件声称的内容是否在摘要中能找到对应？
   - 数字是否一致？
   - 结论方向是否一致（阳性/阴性/中性）？
   - 人群/干预是否匹配？

**判定标准**:

| 判定 | 条件 | 示例 |
|------|------|------|
| ✅ **匹配** | 声称在摘要中明确体现 | 稿件:"ACS降低RDS风险(RR 0.66)" → 摘要含此数据 |
| ⚠️ **部分匹配** | 声称方向正确但细节有偏差 | 稿件:"p=0.00018" → 摘要:"p<0.001" |
| ❌ **不匹配** | 声称在摘要中找不到对应 | 稿件:"X改善远期肺功能" → 摘要仅报告短期结局 |
| 🔍 **需全文验证** | 摘要信息不足以判断 | 声称涉及亚组分析或次要结局 |

### Layer 3: 全文级验证

**触发条件**:
- Layer 2 判定为 🔍 **需全文验证** 的引用
- 所有核心论点引用（作者对某领域做出强结论的引用）
- Critical严重性级别审稿意见涉及的引用

**验证内容**:
- 获取PDF全文（如可获取）
- 定位声称内容的具体段落/表格/图
- 验证数字、统计方法、结论方向

## 二、Agent V（验证Agent）工作流

### Step 1: 构建验证清单

从稿件中提取所有引用标记，构建验证单元：

```json
{
  "citation_id": "C047",
  "ref_number": 12,
  "pmid": "35799269",
  "claims": [
    {
      "location": "§4.3 ¶2",
      "claim_text": "EIC was observed in 28 to 36% of patients...",
      "claim_type": "statistical"  // statistical | interpretive | background
    }
  ]
}
```

### Step 2: 批量获取文献摘要

- 优先从 PubMed E-utilities API 批量获取
- 对于有 PMID 的 → `https://eutils.ncbi.nlm.nih.gov/entrez/eutils/efetch.fcgi`
- 对于仅有 DOI 的 → dx.doi.org 重定向 → 摘要

### Step 3: 逐条比对

对每个验证单元：
1. 读取稿件中的声称段落
2. 读取文献摘要
3. 比对并给出判定
4. 如不匹配，标注偏差类型和严重程度

### Step 4: 生成验证报告

```markdown
# 引用验证报告

## 统计
- 总引用数: N
- 总声称数: M
- ✅ 匹配: X
- ⚠️ 部分匹配: Y
- ❌ 不匹配: Z
- 🔍 需全文验证: W
- 总体通过率: X/M (XX%)

## 不匹配详情

### ❌ C047 — §4.3 ¶2
- **声称**: "EIC was observed in 28 to 36% of patients"
- **引用**: [12] PMID 35799269
- **摘要实际内容**: "EIC was observed in 28% of patients" (only 28%, not 28-36%)
- **偏差类型**: 数字扩大
- **严重性**: Major
- **建议**: 修正为"28%"，或引用支持36%数据的额外文献
```

## 三、成本模型

### 单次验证Token消耗

| 验证层 | Input Tokens | Output Tokens | 单条成本 (Sonnet) |
|--------|:---:|:---:|:---:|
| Layer 1 存在性 | ~300 | ~100 | ~$0.002 |
| Layer 2 摘要级 | ~1500 | ~300 | ~$0.009 |
| Layer 3 全文级 | ~5000 | ~500 | ~$0.023 |

### 批量验证成本估算

| 稿件规模 | 引用数 | 声称数 | Layer1+2总成本 | Layer3附加成本 |
|---------|:---:|:---:|:---:|:---:|
| 小型 (40 refs) | 40 | 60-80 | ~$0.70 | ~$0-0.50 |
| 中型 (100 refs) | 100 | 150-200 | ~$1.80 | ~$0-1.50 |
| 大型 (200 refs) | 200 | 280-350 | ~$3.00 | ~$0-3.00 |

### 成本优化策略

1. **批量API调用**: 一次请求验证多个引用（而非单条单次），减少系统提示重复消耗
2. **本地缓存**: 已获取的摘要存入 `review-pipeline/input/cache/`，重复使用
3. **异步窗口**: 在6个审稿人并行审稿时，Agent V可同时预取摘要
4. **风险分层跳跃**: Layer 2全部通过 → 跳过Layer 3（除非审稿人标记了Critical）

## 四、特殊引用类型处理

| 引用类型 | 验证策略 | 备注 |
|---------|---------|------|
| Cochrane 综述 | 优先验证结论是否为Cochrane的**主要结论**（非亚组/次要结局） | Cochrane摘要结构化程度高，验证可靠 |
| 预印本 | 标记为"预印本 — 未经同行评审"，不进行全文验证 | 在报告中单独标注 |
| 非英文文献 | 仅验证英文摘要（如有），标记语言限制 | 建议作者确认翻译准确性 |
| 书籍章节 | 如无在线摘要，标记为"🔍 无法自动验证" | 需人工验证 |
| 灰色文献 | 如可在线获取 → Layer 2；否则标记 | 报告/指南通常有在线全文 |
| 间接引用 | 标记"作者引用X via Y"，警告可能需要查原始文献 | 需检查是否构成引用失真 |
