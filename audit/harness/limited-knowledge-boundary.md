# 有限知情边界量化标准 (Limited Knowledge Boundary)

> 审稿项目与写作项目**写审分离**的核心执行标准。本文件定义审稿项目可以知道什么、不能知道什么，以及如何验证。

---

## 原则

**审稿人模拟的是"外部同行评审专家"**——他们收到稿件和必要的背景信息，但对写作过程的内部决策、已识别的问题、质量关卡结果等一概不知。

这确保了审稿人不会：
- 被写作项目的"内部合理性"所说服（"我们这样写是有原因的"）
- 产生宽容偏差（"这个问题他们自己已经发现了，就不提了"）
- 继承写作项目的盲区（共享同一套知识边界）

---

## 一、审稿项目可以知道（Disclosure Packet — 6类信息）

### 类别 A: 稿件全文
```
包含: manuscript 完整文本（标题、摘要、正文、引用列表、图表说明）
格式: Markdown / Plain text
*
不包含: 写作过程注释、HTML审计标签、内部标记
```

### 类别 B: 目标期刊信息
```
包含: 期刊名、IF范围、期刊类型（综合/专科/综述类）
包含: 期刊的作者指南关键要求（字数限制、引用格式、结构要求）
不包含: 写作项目对"为什么选择这个期刊"的内部讨论
```

### 类别 C: 综述类型声明
```
包含: 作者声明的综述类型（叙述性/系统综述/荟萃分析/范围综述）
包含: 该类型综述的标准方法论要求
不包含: 写作过程中对综述类型的讨论或变更记录
```

### 类别 D: PICO 框架
```
包含: Population, Intervention, Comparison, Outcome 的声明
包含: 纳入/排除标准的声明
不包含: PICO的制定过程、修改历史、替代方案讨论
```

### 类别 E: 文献检索策略
```
包含: 使用的数据库列表
包含: 检索式（如作者提供）
包含: 检索日期范围
包含: 命中数量
不包含: 检索策略的优化过程、被放弃的检索式、数据库选择的内部讨论
```

### 类别 F: 引用清单
```
包含: 所有引用的 PMID/DOI 列表
包含: 每篇文献的引用类型（原始研究/综述/指南/灰色文献）
不包含: 引用筛选过程、被排除的文献、笔记和内部评价
```

## 二、审稿项目绝对不能知道（Masked Information — 6类禁止信息）

### 禁止类别 X1: 写作过程内部讨论
- 写作Agent之间的通信记录
- 用户与写作Agent的交互日志
- "为什么选择这样写"的内部讨论

### 禁止类别 X2: 已识别但未修复的问题
- 写作项目内部审校（Agent 4）已发现的问题清单
- 前几轮修改中被识别但被标注为"不修复"的问题
- 质量关卡（Gate 1-11）的检查结果

### 禁止类别 X3: 写作Agent内部决策
- Agent的分工和职责定义
- 各Agent的工作流步骤
- Agent内部的状态管理信息

### 禁止类别 X4: 领域本体和证据缺口分析
- `knowledge/domain-ontology.md` 内容
- `harness/evidence-gap-grading.md` 分析结果
- `harness/cross-intervention-matrix.md` 内容
- 理由：让审稿人**独立发现**覆盖缺口，而非对照已有清单验证

### 禁止类别 X5: 历史修改记录
- git diff 和 commit history
- 前几轮的修改内容和原因
- `memory/workflow-evolution.md` 中的流程改进记录

### 禁止类别 X6: 项目效率/安全数据
- `progress/metrics-raw.json` 内容
- 编码Agent的安全审计结果
- Agent运行效率统计

## 三、量化执行标准

### 知情边界检查清单

每次审稿任务启动时，由 Agent P（预处理Agent）执行以下检查：

```
□ B1. Disclosure Packet 仅包含上述6类(A-F)信息，无X1-X6类信息
□ B2. 屏蔽清单中的信息在审稿Agent的系统提示中不可见
□ B3. 审稿Agent的系统提示中不包含写作项目的 CLAUDE.md 内容
□ B4. 审稿Agent不知道写作项目使用的Agent数量和分工
□ B5. 审稿Agent不知道写作项目内部质量关卡的通过情况
□ B6. 审稿Agent的prompt中使用"外部审稿人"角色（角色扮演一致性）
□ B7. 审稿Agent的prompt中不包含写作项目的数据目录结构
□ B8. 审稿Agent的prompt中不包含"这个项目之前写过什么"等上下文
```

### 违规定义

| 违规级别 | 定义 | 示例 | 处理 |
|---------|------|------|------|
| **临界违规** | 审稿人prompt中不含被屏蔽信息，但提示了"可能遗漏了X" | "请注意检查本文是否遗漏了咖啡因"... → 提示审稿人而非让审稿人独立发现 | 删除提示，重新分发 |
| **严重违规** | 审稿人可以看到写作项目的部分内部信息 | 将Gate 4的检查结果传给了审稿人 | 回退审稿，重新构建知情包 |
| **致命违规** | 审稿人实质上是写作项目Agent 4的复制品 | 审稿人的系统提示包含了Agent 4的工作流 | 终止审稿，从根本上重新设计知情边界 |

### 验证协议

每次审稿任务完成后，由 Agent 0（编码Agent）的Part C（安全审计）进行知情边界合规检查：

```bash
# 检查各审稿Agent的prompt中是否含有禁止信息
# 扫描关键词: CLAUDE.md, Agent 0-8, Gate 1-11, domain-ontology, 
#              evidence-gap-grading, cross-intervention, workflow-evolution,
#              metrics-raw, project-status (写作项目)
```
```

## 四、知情边界执行流程

```
写作项目输出
    │
    ▼
┌─────────────────────────────┐
│ Agent P: 预处理Agent        │
│  1. 接收稿件                 │
│  2. 提取 6 类披露信息        │
│  3. 检查是否混入了 X1-X6     │
│  4. 构建 Disclosure Packet   │
│  5. 构建 Masked Info 清单    │
│  6. 执行 B1-B8 检查清单      │
└─────────────┬───────────────┘
              │
              ▼
┌─────────────────────────────┐
│ Agent G: 关卡复查           │
│  验证 GA2: 知情包合规       │
└─────────────┬───────────────┘
              │
              ▼
┌─────────────────────────────┐
│ Agent R1-R6: 审稿人         │
│  仅接收 Disclosure Packet    │
│  不知 X1-X6 任何信息         │
└─────────────┬───────────────┘
              │
              ▼
┌─────────────────────────────┐
│ Agent 0 Part C: 合规审计    │
│  事后检查: 审稿人prompt      │
│  是否含禁止信息              │
└─────────────────────────────┘
```
