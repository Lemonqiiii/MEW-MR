# Harness Engineering — 审稿项目质量保证框架

## 概述

审稿项目的质量保证与可观测层，对审稿Agent的执行质量进行五维度系统性度量：

| 维度 | 核心问题 | 判定方式 |
|------|---------|---------|
| **成功率** | 审稿人是否完成了审稿任务？ | L1 技术成功（自动化）+ L2 业务成功（检出率验证） |
| **效率** | 完成审稿的代价多大？ | 编码Agent自动收集：墙钟时间、工具调用次数、token消耗 |
| **鲁棒性** | 面对不同类型的稿件能否稳定工作？ | 定期用不同类型综述测试 |
| **安全性** | 知情边界是否被突破？ | 编码Agent被动审计 + 知情边界合规检查 |
| **一致性** | 同一稿件多次审稿，结果是否稳定？ | 间隔重审 + 发现一致性diff |

## 架构

```
编码Agent (数据收集)              关卡Agent (质量判定)
    │                                  │
    ├─ progress/metrics-raw.json ──→   ├─ GA3 单审稿人复查
    ├─ git diff                         ├─ GA4 交叉复查
    ├─ 知情边界合规检查                  ├─ GA5 综合质量检查
    └─ 安全审计                          └─ 生成复查报告
```

## 文件说明

| 文件 | 内容 |

## 执行节奏

| 活动 | 频率 | 执行者 |
|------|------|--------|
| 效率数据收集 | 每次审稿任务 | Agent 0 (编码Agent) |
| 知情边界合规检查 | 每次审稿任务 | Agent 0 Part C |
| 单审稿人复查 | 每个审稿人产出后 | Agent G (关卡Agent) |
| 交叉复查 | 所有审稿人通过后 | Agent G |
| 综合质量检查 | 主编综合后 | Agent G |
| 闭环验证 | 写作项目修复后 | Agent 0 + Agent G |
